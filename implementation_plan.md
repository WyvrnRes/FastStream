# Implementation Plan

[Overview]
Transform FastStream's video player UI into a mobile-first, touch-first experience for every device and screen size, adding a compact touch-friendly toolbar, three-zone tap-to-seek/pause gestures with animated feedback, auto-rotate-to-fullscreen plus a manual orientation-lock button, and a cyclable video fit mode (Fit → Stretch → Crop).

FastStream is a vanilla-JS (ES modules, no bundler/framework) browser-extension media player. The UI lives entirely under `chrome/player/` (`index.html`, `ui/*.mjs`, `assets/fluidplayer/css/fluidplayer.css`, `options/defaults/*.mjs`). A custom build script (`build.mjs`) splices this single source tree into Chrome-libre/Chrome-dist/Firefox-libre/Firefox-dist/Web variants — so every change must be made once in `chrome/` and will propagate to all build targets; the `built/` directory is generated output and must never be edited directly.

Today the player already has: draggable/reorderable toolbar groups (`ToolManager.mjs` + `DefaultToolSettings`), configurable single/double/triple click actions on the whole video area (`ClickActions.mjs`, wired in `InterfaceController.mjs`), a play/pause "big circle" pop animation, CSS video transforms (`videoZoom`/`videoRotate`/`videoFlip` via `CSSFilterUtils.mjs`), fullscreen/PiP/windowed-fullscreen plumbing (partly routed through the extension background worker for site-embedded iframes), and a coarse `EnvUtils.isMobile()` UA check used only to disable toolbar drag-and-drop.

This change replaces the whole-video-area click handler with a three-zone (left/center/right) tap system, adds visible/animated seek and play/pause feedback, introduces a new `videoFitMode` option with a toolbar button that cycles Fit/Stretch/Crop and applies `object-fit` to the video element, adds device-orientation-driven auto-fullscreen plus a manual orientation-lock toolbar button using the Screen Orientation API (with graceful fallback), and reworks the control-bar CSS so touch targets are larger and layout is comfortable at phone widths — while keeping the existing dropdown/popup menu paradigm (enlarged, not replaced) and folding lower-priority tools into the existing "more" overflow sheet. Desktop mouse/keyboard behavior is intentionally superseded everywhere per the "full replacement" scope, but option-driven customization is preserved: existing options (`singleClickAction` etc.) remain configurable for the center zone, and keyboard shortcuts retain full parity.

[Types]
New option fields, enums, and small state additions — no TypeScript; this is a vanilla JS codebase, so "types" means new plain-object enum modules and new default-option keys.

- New enum module `chrome/player/options/defaults/VideoFitModes.mjs`:
  ```js
  export const VideoFitModes = {
    FIT: 'fit',       // object-fit: contain (default, preserves current behavior)
    STRETCH: 'stretch', // object-fit: fill (ignores aspect ratio)
    CROP: 'crop',      // object-fit: cover (fills screen, crops edges)
  };
  ```
- New default option keys added to `chrome/player/options/defaults/DefaultOptions.mjs` and mirrored in `chrome/player/FastStreamClient.mjs` constructor `this.options`:
  - `videoFitMode: VideoFitModes.FIT` (string enum)
  - `autoRotateFullscreen: true` (boolean) — enables physical-rotation-triggers-fullscreen behavior
  - `orientationLock: 'none'` (string enum: `'none' | 'landscape' | 'portrait'`) — manual lock state, persisted like other options
- Existing `ClickActions`/`singleClickAction`/`doubleClickAction`/`tripleClickAction` options are kept, but now scope only to the **center** tap zone (previously the whole video area); left/right zones are hard-wired to seek back/forward with animation and are not user-configurable.
- Optional new keybind entries (non-blocking nice-to-have): `'CycleFitMode': 'None'`, `'ToggleOrientationLock': 'None'` in `DefaultKeybinds.mjs`.
- New `DefaultToolSettings.mjs` entries: `'fitmode'` and `'orientationlock'` tool descriptors (`location`/`priority`) so they participate in the existing tool reorder/overflow system identically to `fullscreen`, `pip`, etc.

[Files]
Every file below is under `chrome/` (the single source of truth); `built/` is generated by `build.mjs` and must not be touched.

New files:
- `chrome/player/options/defaults/VideoFitModes.mjs` — enum of fit modes (FIT/STRETCH/CROP), mirrors the style of `ClickActions.mjs`.
- `chrome/player/utils/OrientationUtils.mjs` — new utility class wrapping `screen.orientation` feature-detection, lock/unlock helpers, and a rotation-change watcher, following the static-method style of `EnvUtils.mjs`/`VideoUtils.mjs`.

Modified files:
- `chrome/player/assets/fluidplayer/css/fluidplayer.css` — rework base (non-media-query) rules for `.fluid_controls_container`, `.fluid_controls_bottom_container`, `.fluid_button`, `.fluid_controls_left/right`, `.tools_container_left`, `.fluid_controls_extra_tools`, `.fluid_control_volume_container`, and menu/popup containers to use larger touch-friendly sizes (min ~40-44px touch targets, larger gaps/padding) as the new baseline for all viewport sizes. Reduce the existing `@media (max-width: 850/1000/700/500px)` blocks to only true "extra-small phone" tweaks (~360-400px) since base styles are now already compact. Add new classes: `.tap_zone_left`, `.tap_zone_center`, `.tap_zone_right` (invisible overlay zones for hit-testing, positioned above the video but below the controls bar via `z-index`), `.seek_indicator` (+ `.left`/`.right` modifiers) with `@keyframes seek-flash`/`@keyframes seek-arrow-pop` for animated seek feedback. Add fit-mode CSS: `.video-container > video { object-fit: contain; }` (explicit default) and `.video-container[data-fit-mode="stretch"] > video { object-fit: fill; }` / `[data-fit-mode="crop"] > video { object-fit: cover; }`. Add `.fluid_control_fitmode`/`.fluid_control_orientationlock` button styles consistent with existing `.fluid_button` icon buttons, plus a `.locked` state modifier for the orientation-lock button.
- `chrome/player/index.html` — add new toolbar button markup (mirroring `.fluid_control_windowed_fullscreen`) for `.fluid_control_fitmode` and `.fluid_control_orientationlock` inside `.fluid_controls_extra_tools`, each with `data-tool="fitmode"`/`data-tool="orientationlock"` so `ToolManager` handles them automatically. Add three new sibling `<div class="tap_zone_left/center/right">` elements adjacent to (not inside) `.video-container`, so `InterfaceController.reset()`'s `videoContainer.replaceChildren()` never removes them.
- `chrome/player/assets/fluidplayer/static/icons2.svg` — add new `<symbol>` icon defs for fit-mode (single icon swapped via a `data-fit-mode`-driven title/aria update, matching the existing `fullscreen-in`/`fullscreen-out` swap pattern) and orientation-lock.
- `chrome/player/ui/DOMElements.mjs` — add selectors: `fitModeButton`, `orientationLockButton`, `tapZoneLeft`, `tapZoneCenter`, `tapZoneRight`.
- `chrome/player/ui/InterfaceController.mjs` — the primary logic file:
  - Replace the existing whole-`videoContainer` single/double/triple-click handler block (~lines 423-488, the `clickCount`/`clickTimeout` logic) with three independent tap handlers bound to the three new zone elements: left-zone tap → seek backward by `seekStepSize * 5` (same amount as the existing skip-backward button) + trigger seek animation; right-zone tap → seek forward, mirrored; center-zone tap → reuse the existing `clickCount`/`clickTimeout`/`ClickActions` switch verbatim, just re-scoped to the center zone element instead of the whole video container.
  - Keep the existing hold-to-speed-up block (~lines 384-421), but re-target it from `mousedown`/`mouseleave` to `pointerdown`/`pointerup`/`pointercancel` on `DOMElements.videoContainer` so it works uniformly for touch and mouse across all three zones.
  - Add `showSeekIndicator(direction, amount)` — toggles the `seek_indicator` element's classes to replay the CSS seek-flash animation (same "remove class → force reflow via `offsetWidth` → add class" pattern already used by `playPauseAnimation()`), updates its text (e.g., "+10s"/"-10s"), and applies `.left`/`.right` modifier classes.
  - Add `setupTapZones()` — binds the three zone tap handlers plus the center-zone's existing click-action chain; called once from `setupDOM()`.
  - Add `cycleFitMode()` — rotates `this.client.options.videoFitMode` through `VideoFitModes`, calls `this.client.updateVideoFitMode()`, updates the fit-mode button label/icon, persists via a new lightweight `'playerUIState'` storage key (`Utils.setConfig`/`Utils.getConfig`, same pattern as `VolumeControls.loadVolumeState()`/`PlaybackRateChanger.loadState()` — avoids coupling to the full options import/export flow).
  - Add `toggleOrientationLock()` — cycles `'none' → 'landscape' → 'portrait' → 'none'`, calls `OrientationUtils.lock(...)`/`unlock()`, updates button active state, persists to `'playerUIState'`.
  - Add `setupOrientationAutoRotate()` (called once from `setupDOM()`) — registers `OrientationUtils.watchRotation(isLandscape => ...)`; on rotate-to-landscape, calls `this.fullscreenToggle(true)` if `this.client.options.autoRotateFullscreen`, a video is loaded, and not already fullscreen (tracks that it was auto-triggered via `this.autoRotatedFullscreen` flag so rotating back to portrait only auto-exits fullscreen that was auto-entered, never a user's manual fullscreen).
  - Add `updateFitModeButton()`/`updateOrientationLockButton()` — small UI-sync helpers analogous to `updateFullScreenButton()`.
  - Add `loadPlayerUIState()`/`savePlayerUIState()` — read/write the `'playerUIState'` key via existing `Utils.getConfig`/`Utils.setConfig` helpers (no changes needed to `Utils.mjs`).
  - Wire `DOMElements.fitModeButton`/`orientationLockButton` click listeners + `WebUtils.setupTabIndex(...)` for accessibility parity with existing buttons.
  - Constructor/`setupDOM()` gains calls to `loadPlayerUIState()`, `setupTapZones()`, `setupOrientationAutoRotate()`.
- `chrome/player/FastStreamClient.mjs`:
  - Add `videoFitMode: VideoFitModes.FIT` to `this.options` (constructor), importing `VideoFitModes`.
  - Add `updateVideoFitMode()` — sets `DOMElements.videoContainer.dataset.fitMode = this.options.videoFitMode`, consumed by the new CSS attribute-selector rules; called from `setOptions()` and once after `addVideo()`.
  - Extend `setOptions(options)` to read `options.videoFitMode`/`options.autoRotateFullscreen` when present and call `updateVideoFitMode()`.
- `chrome/player/options/defaults/DefaultOptions.mjs` — add `videoFitMode: VideoFitModes.FIT` and `autoRotateFullscreen: true` (importing the new enum) for forward-compatibility with options export/import, even though the options-page UI itself is out of scope per the "simplified toolbar only" decision.
- `chrome/player/options/defaults/ToolSettings.mjs` — add `'fitmode': {'location': 'extra', 'priority': 700}` and `'orientationlock': {'location': 'extra', 'priority': 800}` entries.
- `chrome/player/ui/ToolManager.mjs` — no structural change; the existing generic `dataset.tool`-driven iteration already handles new buttons automatically. Extend `updateToolVisibility()` with one new capability check: hide the orientation-lock button when `!OrientationUtils.isSupported()`, mirroring the existing `pip`/`document.pictureInPictureEnabled` pattern.
- `chrome/player/options/defaults/DefaultKeybinds.mjs` — optionally add `'CycleFitMode': 'None'`, `'ToggleOrientationLock': 'None'` (non-blocking).
- `chrome/player/ui/KeybindManager.mjs` — optionally wire the two new keybinds to `interfaceController.cycleFitMode()`/`toggleOrientationLock()`, mirroring the existing `ZoomInVideo`/`RotateVideo` pattern.
- `chrome/_locales/en/messages.json` — add new keys: `player_fitmode_label`, `player_orientationlock_label` (plus any state-specific label variants needed for `WebUtils.setLabels`). Only the English locale file is edited; other locale files and the auto-generated `chrome/player/modules/Localize.mjs` TranslationMap are maintainer-only build artifacts (regenerated via `localescript.mjs`/`generate-locales.mjs`) and are out of scope — the extension build reads `_locales/en/messages.json` directly via `chrome.i18n.getMessage`, so this is sufficient for the extension targets; the "web" build will show raw keys until the maintainer regenerates locales, an accepted limitation.

[Functions]
New functions:
- `OrientationUtils.isSupported()` — `return !!(screen.orientation && screen.orientation.lock)`.
- `OrientationUtils.lock(orientationType)` — `async`, wraps `screen.orientation.lock(orientationType)` in try/catch (lock is often only permitted while in fullscreen; falls back to a console warning + `false` return otherwise), returns boolean success.
- `OrientationUtils.unlock()` — wraps `screen.orientation.unlock()` in try/catch.
- `OrientationUtils.watchRotation(callback)` — subscribes to `screen.orientation.addEventListener('change', ...)` (falling back to `matchMedia('(orientation: landscape)')` listener when `screen.orientation` is unavailable, e.g. some iOS Safari versions), invokes `callback(isLandscape: boolean)` on change, returns an unsubscribe function.
- `InterfaceController.showSeekIndicator(direction, amount)` — animates + labels the seek indicator (`direction` is `'left'|'right'`).
- `InterfaceController.setupTapZones()` — binds tap/click handlers to the three zone elements; called from `setupDOM()`.
- `InterfaceController.cycleFitMode()` / `toggleOrientationLock()` / `setupOrientationAutoRotate()` / `updateFitModeButton()` / `updateOrientationLockButton()` / `loadPlayerUIState()` / `savePlayerUIState()` — as described above.
- `FastStreamClient.updateVideoFitMode()` — applies `dataset.fitMode` to `DOMElements.videoContainer`.

Modified functions:
- `InterfaceController.setupDOM()` (~line 322-508) — remove the whole-`videoContainer` `click` listener block (~lines 423-488) and its `clickCount`/`clickTimeout` state; call `setupTapZones()` instead. Keep the hold-to-speed-up block (~lines 384-421) but re-target from `mousedown`/`mouseleave` to `pointerdown`/`pointerup`/`pointercancel`. Add calls to `setupOrientationAutoRotate()` and `loadPlayerUIState()`.
- `FastStreamClient.setOptions(options)` (~line 280-390) — add handling for `options.videoFitMode`/`options.autoRotateFullscreen`, call `updateVideoFitMode()`.
- `ToolManager.updateToolVisibility()` — add one new capability check hiding the orientation-lock tool when unsupported.

Removed functions: none — the old whole-area click handler is inline code (not a named function) being relocated/rewritten, so there is no external migration concern.

[Classes]
New classes:
- `OrientationUtils` (`chrome/player/utils/OrientationUtils.mjs`) — static-method utility class, no instance state, following the exact style of `EnvUtils`/`VideoUtils`/`WebUtils`.

Modified classes:
- `InterfaceController` (`chrome/player/ui/InterfaceController.mjs`) — add ~9 new methods (listed above) and new instance fields (`this.autoRotatedFullscreen`, `this.orientationUnwatch`); constructor/`setupDOM()` gains calls to load persisted UI state and set up orientation watching/tap zones.
- `FastStreamClient` (`chrome/player/FastStreamClient.mjs`) — add `videoFitMode` default option, add `updateVideoFitMode()`, extend `setOptions()`.
- `ToolManager` (`chrome/player/ui/ToolManager.mjs`) — extend `updateToolVisibility()` with one new capability check; no other structural changes.

Removed classes: none.

[Dependencies]
No new npm packages or external libraries are required. The Screen Orientation API (`screen.orientation`) and Fullscreen API (already partially used via `fullscreenToggle()`) are native browser APIs. No changes to `package.json`, `manifest.json` permissions (neither API requires extension permissions), or `build.mjs` are needed — new files (`VideoFitModes.mjs`, `OrientationUtils.mjs`) are plain `.mjs` ES modules automatically picked up by the existing whole-directory splice-copy build (confirmed via `build.mjs`'s `spliceAndCopy(chromeSourceDir, ...)` calls, which copy the entire `chrome/` tree rather than an explicit file manifest).

[Testing]
This project has no automated test suite (`package.json`'s `"test"` script is a placeholder). Validation is manual/functional, following the project's existing lint-then-build-then-manually-verify workflow:
- Run `npx eslint chrome/player --fix` against all new/modified `.mjs` files to match the existing `eslint-config-google`-based style (2-space indent, JSDoc on public methods).
- Run `npm run build` (`node localescript.mjs && node build.mjs`) to confirm the splice-build succeeds without import/export parsing errors — new files must follow the exact `import {X} from '../Y.mjs'` / `export class X` patterns already used throughout the codebase.
- Manual functional verification by loading the unpacked `chrome/` directory as an unpacked extension (`chrome://extensions` → Developer mode → Load unpacked) and/or serving `built/web/player/index.html` locally, using Chrome DevTools device-toolbar/touch emulation and ideally a real Android/iOS device:
  - Tap left/right/center thirds of the video individually confirm seek-back/seek-forward/click-action behavior and animations, and that a center 2x/3x tap still cycles single/double/triple click actions within the existing 300ms window.
  - Hold anywhere on the video (touch and mouse) triggers 2x speed-up after 800ms and reverts on release.
  - Rotate a real/emulated device to landscape auto-enters fullscreen when `autoRotateFullscreen` is on and a video is loaded; rotating back to portrait exits fullscreen only if it was auto-entered.
  - Tap the orientation-lock button cycles none/landscape/portrait, calling `screen.orientation.lock()` and gracefully no-oping (no thrown/unhandled errors) where locking is disallowed (e.g., desktop browsers, or outside fullscreen).
  - Tap the fit-mode button cycles Fit → Stretch → Crop → Fit, visually confirmed against a non-16:9 video.
  - Toolbar reorder/overflow ("more" sheet) still works with the two new buttons participating, and persists via `checkToolsAndSave()`.
  - Existing keyboard shortcuts (`Space`, arrows, `F`, `W`, etc.) still work unaffected on desktop (regression check, since click handling was restructured).
  - Loading a new video (`InterfaceController.reset()`) doesn't remove the tap zones (verified by design: they are DOM siblings of `.video-container`, not children wiped by `replaceChildren()`).
- No new automated test files are added since no test harness exists in this project; introducing one (e.g., Jest with ESM support) would be a separate, out-of-scope infrastructure change.

[Implementation Order]
1. Add `chrome/player/options/defaults/VideoFitModes.mjs` and `chrome/player/utils/OrientationUtils.mjs` (new, self-contained, no dependents yet).
2. Add new SVG icon symbols to `chrome/player/assets/fluidplayer/static/icons2.svg`, new toolbar button markup + tap-zone `<div>`s to `chrome/player/index.html`, with `data-tool` attributes for the two new buttons.
3. Add new selectors to `chrome/player/ui/DOMElements.mjs`.
4. Add CSS: base touch-friendly sizing rework, `.tap_zone_*`, `.seek_indicator` + keyframes, fit-mode `object-fit` rules, and new button styles in `fluidplayer.css`. Validate visually by opening `index.html` directly.
5. Add `'fitmode'`/`'orientationlock'` entries to `ToolSettings.mjs` and `videoFitMode`/`autoRotateFullscreen` to `DefaultOptions.mjs`.
6. Modify `FastStreamClient.mjs`: add `videoFitMode` to constructor options, add `updateVideoFitMode()`, extend `setOptions()`.
7. Modify `InterfaceController.mjs`: remove old whole-area click handler, add tap-zone/seek-indicator/fit-mode/orientation-lock methods, wire new button listeners, re-target hold-to-speed-up to pointer events. This is the largest, most interdependent step — implement after steps 1-6 are complete, then manually smoke-test immediately.
8. Modify `ToolManager.mjs`: add orientation-lock capability visibility check.
9. (Optional) Add `CycleFitMode`/`ToggleOrientationLock` to `DefaultKeybinds.mjs` and wire in `KeybindManager.mjs`.
10. Add new locale keys to `chrome/_locales/en/messages.json`.
11. Run `npx eslint` on all touched files; fix lint issues.
12. Run `npm run build`; fix any splice-build errors.
13. Manual functional verification per the [Testing] section on both desktop (regression) and mobile/touch-emulated (new behavior) environments; iterate on any bugs found.
